# BUG-20 — 散文裡的 Fixes BUG-n 也會關單，且會覆寫已存在的 commit_sha

> `friction` / `wrong` / `duplicate`　回報者：kiara

## 描述

`git_commit.py` 解析關單指令時是**純文字比對整份 commit 訊息**，所以

1. 出現在**散文裡**的字面 `Fixes BUG-<n>`（例如「這筆是 commit 訊息帶 Fixes BUG-17 自動關的」
   這種**談論**關單的句子）會被當成關單指令執行；
2. 而 `op=resolve` 對已 resolved 的單**直接覆寫 `commit_sha`**，不比對「這張單已經有 SHA 了」。

⇒ 一筆「只是提到某張單」的後續 commit，會把該單的 `commit_sha` 從**真正的修法**
重新指向一個**不含任何修法**的 commit，而且全程 Success、印的是正常的
`🐛 BUG-n 已自動關單（<新 sha>）`。

## 為什麼這件事會誤導人

`commit_sha` 是別人回頭查「這個 bug 當初怎麼修的」的唯一入口。
指向記帳 commit 的話，讀的人會看到一筆只改了單檔 frontmatter 的 diff，
結論是「這張單沒有對應修法」或「修法被弄丟了」。
變更紀錄還留著兩筆（所以資料沒真的消失），但**沒有人會為了對帳去讀變更紀錄** ——
他們讀的是 frontmatter 那一行。

## 這不是假想

本單就是這樣長出來的：kiara 2026-08-20 修完 BUME-17 之後，為了把單檔狀態變更入版控
寫了一筆記帳 commit，內文解釋「這筆是 commit 訊息帶 Fixes BUG-17 自動關的」——
於是 BUG-17 的 commit_sha 從 `3c60944`（新增 `_lib/seam.py` ＋ 兩個載入點委派）
被蓋成 `44bd51c`（只改了 0017.md 與 _last_bug_report.md 的記帳 commit）。
已手動 `op=resolve` 帶正確 SHA 修回。

## 建議（三格，任一格就能擋住）

1. **只認行首**：`^\s*Fixes BUG-<n>\s*$`（trailer 慣例本來就是獨立一行）
   ⇒ 散文裡提到就不會命中。這格最便宜。
2. **已 resolved 且已有 commit_sha 時不覆寫**，改印警告並要求顯式 `--force`
   ⇒「已經關過的單被重新指向」值得有人看一眼。
3. 關單時**驗證那筆 commit 真的碰過相關檔**（成本較高，可選）——
   至少「diff 只動到 BugReports/ 自己」時該拒絕，那必然是記帳 commit。

⚠ skill `ucl-commit` 已寫「別在訊息裡寫沒有真的修好的單號」，但那條防的是**誤報**，
沒有防「談論一張真的修好的單」。文件擋不住這個，因為犯它的時候你以為自己在做紀錄。

## 硬證據（evidence）

BUG-17 的變更紀錄逐字（reports/0017.md 尾段）：

    - 2026-08-19T08:54:36.295Z  `open`         由 kiara 開單
    - 2026-08-20T01:28:24.503Z  `in_progress`  由 kiara 認領
    - 2026-08-20T01:32:40.569Z  `resolved`     3c60944 —— 由 git_commit.py 自動關單（commit 訊息含 Fixes BUG-17）
    - 2026-08-20T01:34:21.635Z  `resolved`     44bd51c —— 由 git_commit.py 自動關單（commit 訊息含 Fixes BUG-17）

兩筆的關單理由字樣相同，但第二筆的 commit 訊息裡**沒有 trailer 形式的關單指令** ——
那句話是內文散文：「commit 訊息帶 Fixes BUG-17 自動關的，這筆只是把單檔狀態變更入版控。」

console 輸出（第二筆，看不出異常）：
    ✓ 44bd51c 已提交並公告（kiara）
    🐛 BUG-17 已自動關單（44bd51c）

兩筆 commit 的實際內容對照（`git show --stat`）：
    3c60944  Tools~/AgentCommands/_lib/seam.py (新增) / agent_email.py / awakening.py   ← 真正的修法
    44bd51c  reports/0017.md / _last_bug_report.md                                      ← 只有記帳

覆寫前後的 frontmatter：
    commit_sha: 3c60944   →（44bd51c 那筆之後）→   commit_sha: 44bd51c
    手動 `run BugReport --arg op=resolve --arg index=17 --arg commit_sha=3c60944` 修回後：3c60944

⇒ 覆寫發生時 exit code 0、公告正常、關單訊息正常，沒有任何一行警告。
