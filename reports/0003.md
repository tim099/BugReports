# BUG-3 — op=step 的 step_args 全域逃脫引號，讓帶空白的參數無法分組

> `bug` / `wrong` / `open`　回報者：basecamp

## 描述

`Cmd_FreeTimeActivity.RunToolStep` 把 `step_args` 裡的 `"` **全部**逃脫成 `\"`（單一 Arguments 字串）。
那讓引號變成字面內容 ⇒ **它們再也不能分組**，所以任何「值裡有空白」的參數都會被拆散。

兩個需求互斥，一條全域規則不可能同時滿足：
- `--pixels [{"x":1}]`（無空白）→ 引號要當**內容**，必須逃脫
- `--say "a b c"`（有空白）→ 引號要當**分組**，不能逃脫

成因是我 2026-08-18 上午修前者時的修法，而**我的驗收只有 JSON 那一半** ——
用「同一個 payload 重跑成功」當成修好了，而那個 payload 剛好不需要分組。
（我驗的是我修的那一格，不是那一格所屬的那一類。）

建議修法（別沿用原修法）：改走 `ProcessStartInfo.ArgumentList`（per-arg，.NET 自己做正確逃脫），
`step_args` 先用一個「尊重引號的 tokenizer」切成清單 —— 引號的兩種角色在切詞那一步就分開了，
不必在字串層猜。

## 硬證據（evidence）

run_cmd.py --persona basecamp run FreeTimeActivity --arg op=step --arg persona=basecamp \
  --arg activity=chess --arg step=move \
  --arg step_args='2 e2e4 --persona basecamp --say "自己跟自己下第一手 —— 順便驗 --say 帶中文與破折號穿不穿得過三層"'

→ exit=2
   chess.py: error: unrecognized arguments: —— 順便驗
   （--say 只收到第一個 token，其餘變成散落的位置參數）

對照：同一支 op=step 用無空白的 JSON payload 成功
   --arg step_args='--persona basecamp --pay auto --pixels [{"x":518,"y":497,"color":"#E8B84B"}]'
   → placed 1 pixel(s)（引號逃脫在這一格是必要的）

落點：UCL_Core_Scripts/EditorCore/UCL_AgentCommands/FreeTime/Cmd_FreeTimeActivity.cs
      RunToolStep() 內 Arguments = ... iStepArgs.Replace("\"", "\\\"")
