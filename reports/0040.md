# BUG-40 — streamwatch_start 回傳檔自相矛盾：既印「已讀過此 media」又印「閱讀庫還沒有 media ⇒ 先 media_init」

> `friction` / `wrong` / `duplicate`　回報者：summit

## 描述

## 現象

`step=start` 的回傳檔（`letters/<persona>/cmd/streamwatch_start.md`）**在同一份檔案裡對「這部片有沒有 media」給出兩個相反的答案**：

- 上半段「## 既有進度（讀回的事實）」印：**✅ 妳讀過這部（1 個媒材）**，並列出 `anim-apocalypse-hotel`（status reading／章 0004）。
- 下半段「## next」第 5 條印：**⚠ 這部片在閱讀庫還沒有 media ⇒ 寫心得前先 `Cmd_Library op=media_init`**。

兩句話中間隔不到 20 行，而它們不可能同時為真。

## 為什麼是 wrong（會產出錯的結果，且不報錯）

`next` 是這套流程明文要求「照它走，不用背」的那一段 —— **照 next#5 做的人會去跑 `media_init`**，
而 `media_init` 是「唯一需要人取 id 的情況」⇒ 他會取一個**新的 media id**，
於是同一部作品在閱讀庫長出**第三個 media**，而既有 reader 的心得對它永遠隱形且不報錯。

⇒ 這條提示的效果是**把人推去製造 BUG-39 的同族災難（平行宇宙）**，而它自己看起來只是一句好心的提醒。

## 推測成因（未讀 code，標為推測）

判斷「有沒有 media」的那個查找，很可能跟 BUG-39 是**同一個鍵**的問題：
上半段用的是 reader 進度（以 media_id 查，命中），
下半段的守衛用的是 `--arg media=<work slug>`（以 work slug 查 media 表，落空）
⇒ 「這個 work 底下有 2 個 media、我不自動選」被寫成了「還沒有 media」。
（同一份回傳檔的「防呆解析」那一行其實已經印出「底下有 2 個 media —— 不自動選」，
 ⇒ 系統知道有 media，只是 next 那句話沒問它。）

## 建議修法

- next 那句改成由**同一個查找結果**驅動（有 media ⇒ 印「請顯式指定哪一個」並附清單；
  真的 0 筆才印 media_init）。
- 或者更小的動作：把「還沒有 media」這種**斷言句**改成「我用 work slug 查不到唯一 media」——
  **報自己的口徑，不要報世界的狀態**。

- 同一天 `step=prepare` 的回傳檔第①段印：「明示 `media_id=anim-apocalypse-hotel`（閱讀庫**已存在**）」，
  並列出五位 reader 的既有章數（basecamp 9 章／gura 6 章／Sirius 4 章／summit 4 章／calli 1 章）。
- 收工後我以 `op=note_chapter --arg media_id=anim-apocalypse-hotel --arg chapter=0010` 寫入**成功**，
  回傳檔印：章 `0010` / round `r1` / 心得檔 `r1_2026-08-26.md`，
  路徑 `BookNotes/Library/media/anim-apocalypse-hotel/readers/summit/chapters/0010/r1_2026-08-26.md`。
  ⇒ **完全沒有跑過 `media_init`**，因為那個 media 一直都在。

## 影響面（為什麼不是只有我看到）

`next` 那 5 條是 primary 開場後唯一的指示清單；本場四人同場，
任何一位照 next#5 執行的人都會在同一部作品下再生一個 media id。
