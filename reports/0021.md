# BUG-21 — bank_personas 反向表沒有寫入端 —— 覆蓋率會隨建人安靜衰減

> `bug` / `wrong` / `open`　回報者：kiara

## 描述

§8.1 反向登記（`bank_personas`）是「錢屬於誰」的權威表，但它**沒有任何寫入端**：
C# 零個、python 零個，全樹只有讀取。它今天的內容是 2026-08-19 由人逐位從現況導出後
手寫進 `_registry_meta.json` 的（commit 5394fae1e）。

而**舊方向那張表有寫入端**：`UCL_PersonaAgentAdminPage.DoCreateAgent()` 建 agent 時
`reg["agent_banks"][agent] = bank` 落檔。

⇒ §8.1 只反轉了**讀取**方向，**寫入**方向還在維護舊表。
⇒ 從現在起每建一個 agent／每 fork 一個 persona，反向表的覆蓋率就掉一格，
   而**第一個受害者一定是最新來的那個人**（最不會有人替他複驗的那個）。

## 為什麼今天全綠，而全綠正是誤導的部分

實測（2026-08-20 唯讀探針）：反向表 14 家 bank／登記 21 人、pool 21 人、
未登記 0、重複 0、多餘 0 ⇒ **21/21 都由反向表命中，沒有任何人退到正向鏈**。

看起來像「機制健康」。實際上那只是「那天有個人手抄了一份，而之後還沒有人加入」。
沒有寫入端的權威表，它的正確性是**一次性**的，不是持續的。

## 沒登記會怎樣（分退場前後）

- **退場前（現在）**：退到正向鏈（persona → agent → bank）。Trace 有寫 ⚠ 明示走舊路，
  所以還算誠實 —— 這是它今天不痛的唯一原因。
- **退場後（Phase 3 計畫要刪正向鏈）**：掉到 `Resolve()` 的 ⑥ `Unresolved`
  ——「查無對應，將產生／沿用孤兒帳戶」。錢還是入帳，但入孤兒戶。
  §8.1 拍板的安全網（無登記 → 預設央行 ＋ 酒保通知）**刻意未做**，
  理由是「正向鏈末端會 derive `-da-xiaojie` ⇒ 那條永遠不觸發」。
  ⇒ 正向鏈一走，那格從死碼變成唯一的網，而它現在還不存在。

## 建議（順序不能顛倒）

1. **給反向表寫入端**（本單的主體）—— 建 persona／建 agent／fork 時登記進 `bank_personas`。
   這一步**單獨拿出來也是淨賺**：讓表停止衰減，跟正向鏈什麼時候退場無關。
   ⚠ 放哪待拍：建人流程（`PersonaAgentAdminPage`）還是 `Cmd_Treasury`？
   「錢的歸屬是銀行的宣告」的話該是後者，但那讓建人依賴 Treasury。
2. 再裝 §8.1 的央行 fallback ＋ 酒保通知（前置：python 端補央行常數；C# 已有
   `UCL_CentralBankSettings`）。
3. **然後才**刪正向鏈（C# `s_PersonaToAgentLower` ＋ `Resolve()` ⑤-b、
   python `resolve_persona_bank` ② 段、`agent_banks` 降級）。
4. 那一刻 `UCL_TreasuryAccountResolver` 才不再需要 `PersonasDir`
   （它讀 legacy 的唯一理由就是正向鏈，連快取戳章一起換）。

詳解已發酒館 tavern:2026-08-20#12671。
