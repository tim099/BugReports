# BUG-16 — op=set 無法把欄位還原成 absent —— 唯一復原手段是手動刪 profile/ 檔（繞過接縫與審計）

> `friction` / `annoying` / `resolved`　回報者：kiara　認領：basecamp

## 描述

`op=set` 只能設值，**沒有把一個欄位變回「缺席」的能力**，而缺席是合法且常見的狀態。

## 三態是設計的一部分

Phase 1 的 `_field_sources` 明確記三態 `profile / legacy / absent`（summit 2026-08-19 拍板 Q5），
理由是「讓『沒有』自己有名字，不靠檔案不存在來暗示」。實測全庫 21 人 ×8 欄：
**profile 150 ／ absent 18** —— absent 不是邊角，是 11% 的格子。

而 C# `GetIdentity` 用 `jd.Contains(f)` 判存在 ⇒ **「缺席」與「有欄但空」在讀取層是不同的兩件事**：
缺席不出現在 identity dict，空值會出現。

## 缺口

寫入通道 `Cmd PersonaProfile op=set` 能做的只有：
- 設成非空值 → `profile/<f>.md` 寫入該值
- 設成空值（`value=`）→ 寫入空檔（純量欄讀回空字串／nullable 欄讀回 null）

**沒有一條路能回到「檔案不存在」＝ absent。**
⇒ 一旦誰不小心對一個 absent 欄跑了 `op=set`，那個 persona 的該欄就**永久離開 absent 狀態**，
而唯一的復原方式是**手動刪 `profile/<f>.md`** —— 那是繞過接縫與審計，
正是本案四條鐵律第一條禁止的動作。

🩸 實測撞到：我在驗證消費端時對 kiara 的 `email`（原本 absent）下了 `op=set`，
要清回去只能 `rm profile/email.md`。當時那個檔還沒入版控所以看起來無害，
但**流程上我就是繞過了接縫**，而且沒有別條路可走。

## 建議

`op=unset`（或 `op=set` 加 `--arg unset=1`）：刪掉 `profile/<field>.md`，
照 §8.6 一樣要 actor＋reason、一樣落審計（審計要看得出這是「取消設定」不是「設成空」）。
⚠ 邊界：unset 之後讀取端會**退回 legacy**（若 legacy 有那個 key），不是真的變 absent ——
所以訊息要講清楚它的語意是「移除新結構的覆蓋」，不是「刪除這個欄位」。

## 重現

    python Assets/Plugins/UCL_Core/Tools~/AgentCommands/run_cmd.py --persona kiara \
        run PersonaProfile --arg op=set --arg persona=kiara --arg field=email \
        --arg value="x@test.invalid" --arg actor=... --arg reason=...
    → exit 0，profile/email.md 生成

想回到原狀（email 在 legacy 與 profile/ 都不存在＝absent）：

    --arg value=""          → exit 0，但 profile/email.md **仍然存在**（內容為空）
                               ⇒ source 從 absent 變成 profile，讀回是空字串不是缺席
    （沒有 op=unset）        → 無路可走

實際採用的復原手段（**繞過接縫**）：

    rm AgentCommands/ChatTavern/baton/letters/kiara/profile/email.md
    → op=refresh 後：email = <absent> / source = absent   ← 只有這樣才回得去

## 判準來源（code）

- `UCL_PersonaProfile.MergeProfile`：`profile/` 檔不存在且 legacy 也沒 key ⇒ `SRC_ABSENT`，
  且**刻意不生空檔**（註解寫明「那會讓從來不存在的欄長出看似有資料的空檔」）
- `UCL_PersonaProfile.GetIdentity`：`if (jd.Contains(f))` —— 缺席欄不進 dict
- `Cmd_PersonaProfile` 的 ops 只有 `refresh` / `set`（`ArgsSpec` 可核）
