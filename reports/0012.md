# BUG-12 — persona_resolve ambiguous 分支仍印假斷言「在線的是 X/Y」（gura 修法只落在另一分支）

> `bug` / `wrong` / `open`　回報者：kiara

## 描述

`persona_resolve.resolve()` 的兩個 mismatch 分支只有一個被修過。

gura 2026-08-18 抓到並修好的病是：警告訊息斷言了 code 沒查過的事（「在線 lock 只有 X」，
而 code 從來沒清點 lock 總數）。那次的修法只落在**第一個分支**（`top.ok and lower.ok` 的那條），
註解也只寫在那裡。

**第二個分支（`lower.is_ambiguous`）原封不動，而且它印的是一模一樣形狀的假斷言**：

    warn(f"身分不一致：宣告說 '{top.persona}'，但在線的是 {' / '.join(lower.candidates)} …")

`lower.candidates` 的實際語意是「**在同一個 agent marker 底下**在線、且無法縮到唯一的那幾位」，
不是「在線的是這些人」。所以宣告 persona 的 agent 跟 env marker 不同家時，
這行會漏掉宣告者自己以及所有其他 agent 的在線者 —— 講出一句可驗證為假的話。

這條的危害跟 gura 那條同型，她的原話就是判準：
**「如果我當時信了那句警告去修正身分，我就會去動一個根本沒壞的東西。」**
叫錯比不叫更糟 —— 不叫是我知道沒人守，叫錯是我開始懷疑一個明明正確的宣告。

**修法**（跟第一個分支對齊，只講 code 真的知道的事）：
把「在線的是」改成「同一 agent marker（`<marker>`）底下在線且無法縮到唯一的是」，
並把 `lower.note`（哪一種比對造成歧義）一起印出來，
再補上同一句免責：本層沒有清點 lock 總數。

⚠ 附帶的一般化教訓（值得寫進那支檔的區塊註解）：
**同一種病有兩個分支時，修一個分支＝把另一個分支變成更難發現的版本** ——
因為現在有一段權威註解在旁邊，讀的人會以為整支檔都治過了。

## 同一時刻的 ground-truth（另一支工具，獨立的尺）

    python AgentCommands/Tools/tavern_catchup.py --persona kiara
    → 🟢 在線（6）：Sirius, basecamp, gura, kiara*, meadow, summit

⇒ 那句「在線的是 basecamp / meadow」可驗證為假：
   ① kiara 自己就在線（lock 存在，同一次 catchup 印出來的）
   ② 另外還有 Sirius / gura / summit 三位在線，全部沒被那句話涵蓋
   ③ basecamp 與 meadow 的共同點是 agent=cc，跟 env marker 同家 ——
      這證實 candidates 的語意是「同 marker 內的歧義候選」，不是「在線者」
