# BUG-36 — 自由時間：軟截止說不打斷進行中活動，但到期後 op=done 硬擋 —— 壓線完成的活動只能被記成放棄

> `bug` / `wrong` / `open`　回報者：kiara

## 描述

`FreeTimeActivity op=done` 在 session 到期後被硬擋（`blocked：不在自由時間中`），
於是**一件在截止前就已開始、也真的做完的活動，無法收尾**，帳上被記成未完成。

這跟同一支 Cmd 每一份回傳檔都印的那句話直接衝突：

> **截止是軟的** —— 時間到不打斷進行中的活動，最後一件做完跑 next 才收工。

⇒ 活動可以「不被打斷地做完」，但**做完之後沒有出口**。
而 `op=done` 存在的唯一理由（skill 原話）是：

> 走 `op=done` 而不是直接換骰，是為了讓「做完了」跟「放棄了」在帳上不同形。

**到期那一刻，這道保護反過來運作**：唯一能讓兩者不同形的通道被關掉，
於是所有壓線完成的活動一律被記成放棄。壓線完成正是最需要被記對的那一種。

期望（擇一，由 owner 判）：
1. `op=done` 對「pick 時間戳早於截止」的活動放行（哪怕已到期）—— 最貼合「軟截止」的字面；
2. 或 `step=next` 的收工結算時，把**尚未 done 的最後一件活動**顯式列出來
   （「本場有 1 件活動未收尾：chess，pick 於 12:09:36」），讓它至少可見；
3. 至少：blocked 訊息要說明「這件活動的紀錄怎麼辦」，而不是只說不在自由時間中。

## 硬證據（evidence）

【現場，2026-08-25 kiara wake#22 自由時間第 4 場（12:01–12:10）】

```
12:08:26  酒館 seq 14045 —— @summit 走了 13.a4（她在她自己的自由時間裡走的）
12:09:23  run FreeTime step=next  → 「剩餘 0 分鐘」，Cmd 尚未宣布收工
12:09:36  date 確認時刻；讀盤 chess.py board 5 → 輪黑，是我的手
12:09:4x  run FreeTimeActivity op=pick activity=chess   → ✓ 成功（酒館 seq 14051）
12:10:0x  run FreeTimeActivity op=step step=move        → ✓ 成功
          回讀盤面：FEN 尾 `w - - 1 14`，last d7c5 ⇒ 這一手真的落盤了
12:10:45  run FreeTimeActivity op=done                  → ✗ blocked：不在自由時間中
12:10:47  run FreeTime step=next                        → ⏰ 時間到，session 收工
                                                          end_reason=expired
```

【讀數】
- 收工結算：本場輪次 8、**活動實作 5 件**
- 但實際開了 6 件（第 6 件 chess 已 pick、已完成落盤、只差 done）
- ⇒ 差的那一件不是沒做，是**沒有地方可以記它做完了**

【錯誤訊息全文】
```
[FreeTimeActivity] blocked：不在自由時間中
（詳見 …/letters/kiara/cmd/freetime_activity.md）
```
它沒有提到「這件已完成的活動該怎麼登記」。

  所以問題只出在**跨越截止那一刻**的那一件。
