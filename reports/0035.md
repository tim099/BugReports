# BUG-35 — awakening.py consolidate 寫入成功卻 exit 1：收尾誤走已退場的 save_registry（紅字還指到別人的 identity 欄）

> `bug` / `wrong` / `open`　回報者：kiara

## 描述

`awakening.py consolidate --persona <P> --digest-body "<...>"` 的 digest **實際上寫成功了**，
但指令以 **exit 1** 收尾，畫面只有一條跟本次操作無關的紅字：consolidate 收尾時把整份中央 registry
（含**別人**的 `Sirius` identity 欄）往 `save_registry` 送，撞到 2026-08-21「中央 personas/ 退場」守衛。

為什麼這不只是噪音：
1. **成功與失敗同形** —— 呼叫端看到紅字＋非零退出，正常判讀是「見林濃縮失敗要重跑」；
   重跑會拿到「gap: 0／待濃縮 0 封」，agent 得自己翻 `longterm/` 才知道其實成功了。
   早安儀式把見林 OVERDUE 列為 **required**，這一格會讓人以為 protocol 沒走完。
2. **錯誤訊息指錯地方** —— 它教人去跑 `PersonaProfile op=set` 改身分欄，但呼叫端根本沒有要改任何身分欄。
3. 受影響的 persona 是 `Sirius`（不是被 consolidate 的那位）＝ consolidate 讀了整份中央 registry 又原樣寫回，
   那條路在退場後已經不該存在。

期望：consolidate 的進度推進不要再經過 `save_registry`（進度欄應落在 `letters/<persona>/` 底下）；
至少寫檔成功後不得以 exit 1 收尾，且訊息要明說「digest 已寫入」。

## 硬證據（evidence）

【復現】
1. gap >= 門檻的 persona 跑 `awakening.py consolidate --persona kiara` 取得 span（本次 11-22，15 封）
2. 帶 digest 再跑：`awakening.py consolidate --persona kiara --span-start 11 --span-end 22 --digest-body "<濃縮>"`
3. 觀察：exit code = 1，stdout 只有下面那條紅字

【實際輸出】
```
❌ [awakening] save_registry 收到 identity 欄（Sirius: ['layer_role', 'forked_from', 'fork_lineage', 'forked_at', 'created_at', 'identity_vector', 'vector_history', 'model', 'actual_agent']）—— 停手。
   persona 資料已整合到 letters/<persona>/profile/，中央 personas/ 退場（2026-08-21）。
```
