# BUG-5 — _lib/ucl_paths.py 有兩份 → wake brief 關係區塊靜默退成假的空狀態

> `bug` / `wrong` / `resolved`　回報者：calli　認領：calli

## 描述

## 現象

早安 `step=brief` 生成 wake brief 時 stderr 吐一行：

```
[wake_brief] relationship 路徑解析失敗：cannot import name 'letters_persona_dir'
from '_lib.ucl_paths' (D:\Unity\Bar\AgentCommands\_lib\ucl_paths.py)
```

而**主流程 exit=0、Cmd 回 Success、brief 照樣印 849 行**、回傳檔照樣寫「✅ wake brief 生成」。
代價是 brief §6.5 少了 relationship（關係讀數）整段，底下印的是：

> _(還沒有關係紀錄 —— 跟同事互動後走 `ucl-relationship` 寫一筆)_

⚠ **那句話是假的**：relationship 系統昨天（wake#23）剛上線並完成遷移，資料是有的。
這不是空狀態，是**import 失敗被 fail-soft 吞成空狀態，然後空狀態被印成一句肯定句**。

## 病灶（已定位，不是假說）

**`_lib/ucl_paths.py` 有兩份，wake_brief.py 撈到的是舊的那份。**

| 檔案 | 大小 / mtime | 有 `letters_persona_dir`？ |
|---|---|---|
| `Assets/Plugins/UCL_Core/Tools~/AgentCommands/_lib/ucl_paths.py` | 30420 / **Aug 18 20:05** | ✅ 有（第 381 行） |
| `AgentCommands/_lib/ucl_paths.py` | 29270 / **Aug 17 19:39** | ❌ 沒有（只有 `letters_root`） |

`wake_brief.py:854` 寫 `from _lib.ucl_paths import letters_persona_dir`，
而錯誤訊息裡的解析結果是**專案層那份舊的**（`D:\Unity\Bar\AgentCommands\_lib\ucl_paths.py`）。
⇒ 病不在函式名改錯，是 **同名模組有兩份、sys.path 撈到舊的那一份**；
UCL_Core 端昨天長出的新函式，專案層那份沒有。

## 為什麼這條值得開單（不只是少印一區）

1. 讀 brief 的人就是**剛醒來、最沒有 context 的那個人**。他看到「你還沒有關係紀錄」，
   而事實是「關係紀錄讀不到」——**這兩句話導向相反的行動**：前者叫我去寫一筆新的（製造重複資料），
   後者叫我去修路徑。
2. stderr 那行只在跑 Cmd 的人眼前閃一次（我是在 step=brief 回傳檔裡才看到），
   **brief 本體裡沒有任何痕跡** ⇒ 明天讀 brief 的人沒有機會知道那一區壞了。

## 建議修法（兩條各自成立，②比①重要）

1. 讓 `_lib` 只有一個真相源（專案層那份補上 / 改成轉發 / 或 wake_brief 顯式吃 UCL_Core 端）——
   由拍板的人決定哪一邊是本體；⚠ **同名雙份模組會繼續生同族 bug**，不只這一個函式。
2. **fail-soft 要留，但不准說謊**：解析失敗時那一區要印
   「⚠ relationship 區塊生成失敗：<err>（不是沒有紀錄）」，
   而不是退回「還沒有關係紀錄」。①修完，②沒修的話下一次同族失敗照樣靜默。
