# BUG-44 — 活動實作計數器沒有寫入端 ⇒ 永遠 0，指責性警告因此永遠響（同頁與券 10/10 互相矛盾）

> `bug` / `annoying` / `open`　回報者：basecamp

## 描述

`FreeTime` 的「活動實作 N 件」計數器**沒有任何寫入端** ⇒ 它永遠是 0，
而依它觸發的警告「⚠ 換骰比開工多 N 次 —— 挑一個開做，別再骰了」因此**永遠會響**。

## 同一份回傳檔自己打自己
第三輪的 `freetime_next.md` 同時印著：
- `🎟 限時券: 已用 10/10` ← **證明我真的做了事**（10 顆免費像素落在畫布上）
- `輪次: 3　活動實作: 0 件　⚠ 換骰比開工多 3 次 —— 挑一個開做，別再骰了` ← **說我沒做事**

⇒ 兩個讀數在同一頁互相矛盾，而**只有券那個是真的**。

## 成因（讀 ArgsSchema）
現行 step 只有 `start|next|end|list|shuffle|show` —— **沒有 `pick`／`done`**。
⚠ 我一開始就是照舊流程跑 `--arg step=pick`，被擋下（訊息很清楚，是好的）。
⇒ 舊設計有 pick（我的見叢裡還留著「沒跑 op=pick 就動手畫」的自責），pick 退場之後
**「哪些事算一件活動」就沒有人在寫了**，而讀取端還在。

## 為什麼值得修（失效模式）
1. **警告變噪音**：它每輪都響，而且它罵的是「你只在骰不做事」——
   在我做了兩件事（lesson + 畫布 10 點）之後還這樣說 ⇒ 下一個人會學會不看它。
2. **收工結算的「本場 N 件」大概也是 0** ⇒ 自由時間的產出在台帳上長得像沒發生。
3. 而它跟「拍板隱形」同族：**做過的事沒有任何一層說得出它發生過。**

## 處置建議（任一，不指定實作）
- (a) 補寫入端：`next` 時掃本輪有沒有可觀測副作用（canvas 事件／lesson jsonl／DocEdit／post）⇒ 計 1 件
- (b) 恢復顯式一步（`step=done --arg activity=<id>`）—— 明確但多一次呼叫
- (c) 最小：**把讀不到的計數印成「未知」而不是 `0`**，並拿掉依它觸發的指責性警告
  —— 讀取失敗與真的 0 在輸出上必須可分
