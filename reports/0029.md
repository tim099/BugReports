# BUG-29 — Phase 1 殘留補掃：Cmd_GoodMorning 直讀 legacy layer_role、LoginStatusPage 直寫 legacy 繞過審計

> `bug` / `wrong` / `open`　回報者：basecamp

## 描述

Phase 1 之後仍有兩處 C# 繞過 UCL_PersonaProfile 接縫直碰 legacy persona json，BUG-18 的殘留清單裡沒有它們（今天實掃補上）：

① **讀** `Cmd_GoodMorning.cs:152-155` —— 自介標頭走 `UCL_PersonaData.LoadFromFile(PersonasDir/<p>.json)` 直讀 legacy 拿 `wake_count` 與 `layer_role`。
   `layer_role` 是 identity 欄、真相源已在 `letters/<p>/profile/layer_role.md`。
   ⇒ 有人改過 profile 的 layer_role 之後，早安自介的 Layer 那行會印**舊值**，而沒有任何一格會紅。
   今天不痛的理由：legacy 只出不進＝值仍等於遷移那一刻，且 wake_count 剛被登入 patch 過（實測 wake#67 印對）。
   修法：改走 `UCL_PersonaProfile.GetRaw/GetString`（同 Cmd_LoginStatus 既有寫法）。

② **寫** `UCL_LoginStatusPage.ApplyActualAgent`（738-768）—— 直接 `File.ReadAllText` legacy → 改 `actual_agent` → 自己 `AtomicWriteUtf8` 寫回整檔。
   繞過 `UCL_PersonaProfile.WriteRaw` ⇒ 沒有 §8.6 的 actor/reason 審計、沒有 `FreezeLegacyIdentity`、沒有快照刷新。
   `actual_agent` 是 routing 欄（legacy 仍是它的家），所以資料不會錯；壞的是**這筆改動不會出現在 `_persona_write_audit.jsonl`**。
   修法：改走 WriteRaw（actor=UCL_LoginStatusPage、reason=套用實際 Agent）。

③ 附帶：`AgentCommands/_lib/affinity_manager.py:329` 是全樹唯一**寫死** legacy 路徑的檔（不走 ucl_paths 解析點），而它今天全樹 **零 importer**（只有自己 import 自己）⇒ 建議跟 Phase 3 一起刪，不必先遷。
