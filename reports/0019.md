# BUG-19 — tier-3 local-parse 讓 commit trailer 寫出別人的信箱（不可改產物）

> `bug` / `wrong` / `duplicate`　回報者：kiara

## 描述

Phase 2 觀察期實測到的第一筆「消費端拿到舊值」——而且落點是 git history，改不掉。

## 現象
persona 的 email 已於 Phase 1 遷進 letters/<p>/profile/email.md。
接縫 persona_profile 的 tier-1（Cmd）/ tier-2（快照）看得到新值；
tier-3（local-parse）**依設計讀 legacy AwakenInit/personas/*.json，看不到 profile/**（§8.4 刻意不修）。

問題不在 tier-3 會舊 —— 那是拍過板的。問題在：
1. agent_email.resolve_email 只回 source=persona-override / agent-default / fallback / unset，
   **不傳遞接縫的 _source**；build_trailer 也不看。
2. legacy 的 email 對多數人是 null ⇒ tier-3 落到 defaults[actual_agent] 的 agent 預設信箱，
   得到一個**格式完全合法、屬於別人**的地址；gura 的 legacy 甚至存著 basecamp 的地址。
3. ⇒ tier-3 時 trailer 會寫出別人的信箱，且 looks_like_email() 過、cmd_resolve 不回非零、
   沒有任何一行警告。而 commit trailer 是**不可改的**。

## 為什麼 tier-3 不是假想情境
快照檔 _persona_profile_snapshot.json 是 gitignored（C# 只寫）⇒
**任何 fresh clone 在 Unity 第一次開起來之前都在 tier-3**，而 git commit 不需要 Editor。
即「剛 clone 完先 commit 一筆」＝ 100% 命中。

🩸 同族已流過血：2026-08-19 Tim 設 kiara 的 email 落在 profile/，而當時 agent_email 直讀 legacy
⇒ 4c0f568 之前兩筆 commit 掛的是舊信箱，已成既成事實（Plan §4.1 血證段）。
這次是同一個形狀換一層：那次是「消費端沒走接縫」，這次是「走了接縫但退到 tier-3」。

## 建議修法（未動手，等拍板）
resolve_email 把接縫的 _source 一起回傳；build_trailer 在 _source=local-parse 時
**fail-loud**（拒寫或大聲警告），理由：trailer 是不可改產物，「可能是舊值」對它等於不可接受。
現在的 _source 標記活在回傳值上，但沒有任何消費端把它端到人眼前 ——
標記存在 ≠ 兩態不同形（§8.7 #6 的精神在消費端這一段斷了）。
