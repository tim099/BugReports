# BUG-1 — AI_READABILITY_GUIDELINES 的 related 用裸相對路徑，Viewer 點不到

> `doc` / `wrong` / `resolved`　回報者：calli　認領：calli

## 描述

`Docs/AI_READABILITY_GUIDELINES.md` 的 frontmatter `related:` 用的是**裸相對路徑**
（`Agent/Code_Comment_Standards.md`、`../Assets/Plugins/UCL_Core/Docs~/...`），
而 `UCL_URL.ResolveURL` 對沒有 prefix 的路徑走 `Path.GetFullPath(url)` ——
**那是相對於 process CWD（Unity 專案目錄），不是相對於文件自己所在的目錄**。

⇒ 在 UCL_MarkdownViewerPage 裡點那些關聯按鈕會失敗（`OpenRelated` 找不到檔案 → LogError）。

而這份文件是**專案共用規範的本體**，被 CLAUDE.md 指名為「開工前先讀那份」——
新來的 agent 照它的樣子抄 related 寫法，就會複製這個壞掉的慣例。
（今天 HScene 文件互鏈時我原本就打算照抄它，查了 ResolveURL 才發現不能抄。）

修法：改用 `repo:` prefix（`repo:Docs/Agent/Code_Comment_Standards.md`），
錨在 git repo 根，`UCL_CoreDocsBootstrap` 專為此註冊。

## 硬證據（evidence）

1. `UCL_URL.cs:222-240`：無 prefix 分支是 `url = System.IO.Path.GetFullPath(url)`，
   沒有任何「相對於文件所在目錄」的處理。
2. 該檔 related 第 2 條寫 `Agent/Code_Comment_Standards.md`，
   解析結果會是 `<UnityProjectDir>/Agent/Code_Comment_Standards.md`；
   實測 `ls D:/Unity/LY/Agent/` → 不存在（真正的檔在 `Docs/Agent/` 底下）。
3. 對照組：改用 `repo:` prefix 的路徑實測可解析 ——
   `Cmd_Invoke UCL_URL.ResolveURL("repo:Docs/API/HScenes/HSceneAssets/SatisfiedSetting.md")`
   → `D:\Unity\LY\Docs\API\HScenes\HSceneAssets\SatisfiedSetting.md`（AgentCmd:Invoke OK）
