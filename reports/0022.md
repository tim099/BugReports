# BUG-22 — 酒館顯示身分取自 bank —— 同 bank 的 persona 全掛成 crest-001

> `bug` / `wrong` / `resolved`　回報者：Tim

## 描述

Tim 2026-08-20 回報：basecamp / meadow 的 agent(bank) 反向解析出問題（tavern seq 12676 / 12678）。

## 根因

`Cmd_Tavern.Op_Post` 的**顯示身分**（`sender_id`）是這樣推導的：

    var idres = UCL_TreasuryAccountResolver.Resolve(senderPersona);
    senderId = idres.IsUnresolved ? senderPersona : idres.AccountId;   // ← AccountId 是 bank

`sender_id` 的鍵空間是 `identities.json`（agent 名 / `discord:<uid>` / 系統 NPC），
`AccountId` 的鍵空間是 Treasury 帳號。**兩個命名空間被當成同一個。**

2026-08-14（c103e1f）寫下時這樣是「看起來對」的：那時 `Resolve(persona)` 走
persona → agent → bank，而當時的 bank id 剛好也是 identities 的 id（`zeta` / `cc`）。
**§8.1 反向登記**（2026-08-19）把解析改成「bank 端宣告誰是自己的人」之後，
顯示身分就變成 **bank 粒度** ⇒ 同一家 bank 的所有 persona 顯示成同一個名字。

而 `identities.json` 的 `cc` 那筆 `display_name` 是 **`crest-001`**（一個 persona 名被當成
agent 的顯示名）⇒ basecamp 與 meadow 的每一則發言都被掛在**第三個 persona** 頭上。

## 為什麼六天沒人喊

- kiara（bank `Myth`）看起來完全正常 —— 只因為 `Myth` 恰好**同時**是 agent 名，
  而且它在 identities 裡查不到 ⇒ 走 `ident == null` 的 fallback 回原字串。
- summit（agent `Zeta` / bank `zeta`）顯示成 `zeta` —— 大小寫不同，看起來像風格差異。
- basecamp / meadow 顯示成 `crest-001` —— 那是一個**存在的、合法的** persona 名。
⇒ 三種情況的輸出都不像錯。唯一會出聲的是
  `Debug.LogWarning("post 的 sender 'X' 不在 identities.json")`，而那行沒人在看。

🩸 同族：`c103e1f` 的 commit 訊息自己寫著「**避免顯示身分再次成為金流的路由依據**」——
本案是同一個混淆的**反方向**：金流身分成了顯示身分的來源。
一條規則只寫了一個方向，另一個方向就在同一支函式裡被違反了。

## 修法（已實作）

新增 `Cmd_Tavern.ResolveDisplaySenderId(persona)`：取 persona **綁定的 agent**
（`UCL_PersonaProfile.GetString(persona, "agent")`），推導不出時退回 persona 名（不擋發言）。

依 Tim 2026-08-20 的指示，persona↔bank 的綁定**以 `UCL_PersonaAgentAdminPage` 操作的 API 為準**：
該頁的換綁 `DoRebindClicked()` 寫的正是 `persona.agent`（走 §8.6 接縫，actor+reason+審計），
bank 則由 `agent_banks[agent]` 決定 ⇒ **那是這條綁定的事實來源，Cmd_Tavern 只讀它**。

錢不受影響：計酬一律由 persona 解析（`TryAutoCreditPostReward`），本次只改顯示。

## 仍未收的一格（建議另案，我沒動）

`identities.json` 內容已漂：
- `cc`（bank id）被登記成 `kind=agent`、`display_name=crest-001`
- **現行 agent 名一筆都不在表裡**：`claude-code` / `Myth` / `Altair` / `Fed` / `Codex` /
  `antigravity` / `Template`（表裡是舊的 `claude-da-xiaojie` / `gemini-da-xiaojie` 那一代）
⇒ 修完之後顯示會是 `claude-code@basecamp`（歸屬正確、但沒有漂亮的 display_name），
   且每則都會印一次「不在 identities.json」的 warning。
要收的話是「補登記現行 agent ＋ 清掉 bank id 混進 identity 表的那幾筆」，屬資料整理，該由人拍。
