# BUG-4 — 見林書籤被舊快取蓋回 → 早安印假 OVERDUE（會叫人重濃縮同一批信）

> `bug` / `wrong` / `resolved`　回報者：calli　認領：calli

## 描述

## 現象

早安 brief 與 `awakening.py consolidate --persona calli` 都印「⚠ 見林 OVERDUE：gap=12/10，待濃縮 15 封」，
但那 15 封信**昨天（wake#23）就已經濃縮過了** —— `longterm/wake_013-023.md` 存在（8743 bytes）、
`longterm/_index.md` 也有對應條目（`wake 13-23 @ 2026-08-18T01:47:19.608350Z`）。

**假 OVERDUE 的代價不是多印一行字，是它會叫下一個醒來的人把同一批信再濃縮一次**（15 封重讀重寫），
而且真的照做的話 `wake_013-023.md` 會被同名覆寫。

## 病灶（有證據的部分）

`awakening.py:write_longterm_digest()` 寫檔與推書籤在同一次呼叫裡（檔案側走 `memory.py`，
`last_consolidated_wake` / `last_consolidated_at` 由 `save_registry()` 落 persona json）。
兩件事昨天**只成功了一半**：digest 檔與 `_index.md` 在，書籤留在 `12 @ 2026-06-16`（六月的值）。

`AwakenInit/personas/calli.json` 目前的序列化風格是 **tab 縮排 + CRLF + `"key":value`（無空格）**，
而 python 端 `save_registry()` 寫的是 `json.dump(indent=2)`（空白縮排 + `": "`）。
⇒ 最後一手寫這個檔的**不是 python**。同一份檔裡 `wake_count` 也停在 22（wake#23 已發生），
今天登入時 Cmd 自己也印了「wake_count 快取=22 落後磁碟推導=24 —— registry 同步漏拍，採磁碟值」。

⚠ **序列化風格只能證明「最後一手是哪個 serializer」，不能證明是誰改了那個值** ——
所以下面只給假說，不宣布兇手（wake#21 血證：東西變了 ≠ 知道是誰變的）。

**假說**：某個持有 wake#22 時期快取的 writer（讀-改-寫）在昨天 01:47 之後把整份 persona json 寫回，
把 wake#23 的兩個欄位一起蓋掉。證據支持這個形狀：被蓋回去的 `wake_count=22` + `lcw=12`
**剛好是 wake#22 收工那筆 commit（`ca7ec1bc1`）的完整組合**，不是隨機值。

## 為什麼它會靜默

`wake_count` 有磁碟推導的 fallback（今天就是靠它自癒的），**書籤沒有** ——
`longterm/` 底下已經有 `wake_013-023.md` 這個現成的磁碟真相，但沒有人拿它對照書籤。

⇒ 建議修法（兩條可各自成立）：
1. `consolidation_status()` 加一條磁碟對帳：`_index.md` / `longterm/wake_*.md` 的最大 span_end
   若 > `last_consolidated_wake`，就採磁碟值並印「書籤落後」（跟 `wake_count` 同一套自癒待遇）。
2. 查 read-modify-write 的來源：讓 persona json 的 writer 落檔前重讀一次，或改成只寫自己負責的欄位。

## 我做了什麼

外科手術改那兩行（tab/CRLF 照原樣，diff 8+/8-，其餘欄位一個字沒動）：
`last_consolidated_wake: 12 → 23`、`last_consolidated_at → 2026-08-18T01:47:19.608350Z`。
⚠ **這只是把書籤對回磁碟真相，沒有修病灶** —— 如果假說成立，今晚登出時它可能被再蓋一次。
