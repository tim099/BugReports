# BUG-42 — NoteLesson 靜默丟欄位：actor 落成 unknown（--persona 已給），title/tags 整個不進 jsonl

> `bug` / `wrong` / `duplicate`　回報者：summit

## 描述

## 現象

`run_cmd.py --persona summit run NoteLesson --arg title=... --arg-file body=... --arg tags=...` 回報 Success，
lesson 也確實 append 進 `AgentCommands/Lessons/lessons.jsonl` —— **但落盤紀錄只剩三個欄位**：

```
{'ts': ..., 'actor': 'unknown', 'category': 'general'}   # ＋ body
```

三件事同時無聲掉了：
1. **`actor` = `'unknown'`**，而我明確傳了 `--persona summit`（同一次呼叫的 queue 路由是正常的：
   回傳檔正確落在 `letters/summit/cmd/notelesson_last_op.md`）。
2. **`title` 沒有進紀錄**（我傳的 title 完全不存在於 json）。
3. **`tags` 沒有進紀錄**（同上）。

回傳檔標題印的是「📝 Lesson noted (general)」，看起來完全成功。

## 為什麼是 wrong（不是 annoying）

- **lesson 庫的用途是跨 session／跨 agent 回查**（skill `agent-lessons-log` 的存在理由）。
  `actor='unknown'` ⇒ 那筆教訓**永久失去歸屬**：後人無法知道是誰踩的、要去問誰、跟誰的見叢對得上。
- 沒有 `title` / `tags` ⇒ **只能全文掃**。而全文檢索失敗的樣子跟「這條教訓不存在」一模一樣
  （這正是本 skill §6 自己寫的那條血證：關鍵字查失敗不會叫）。
- ⇒ 淨效果：**寫進去了，但下一個人找不到、也不知道問誰** —— 一筆看起來成功的落盤，實際上是半個 no-op。

## 疑問點（給修的人，未讀 code，標為推測）

- `--persona` 有兩個作用（queue 路由 ＋ 戳進 args）。本例**路由生效、actor 沒生效**
  ⇒ 懷疑 NoteLesson 的 handler 讀的是另一個欄位名（例如 `agent` / `reporter` / `actor`），
  而不是 `persona`；且缺值時**填了 `'unknown'` 而不是 blocked**。
- `title` / `tags` 我是照 skill 的精神自己取的參數名（skill 只寫「走 Cmd_NoteLesson 自動 append jsonl」，
  **沒有列參數表**）⇒ 若正確參數名不是這兩個，那 **未知參數被靜默忽略**本身就是第二隻：
  打錯參數名應該 blocked 並列出可用參數，而不是收下、回 Success、丟掉內容。

## 建議修法

1. `actor` 缺值時**不要填 `'unknown'`** —— 直接 blocked 並指出要帶什麼（哨兵值不要跟合法值共用一格）。
2. `--persona` 既然已經戳進 args，NoteLesson 應該直接採用它當 actor。
3. **未知 `--arg` 一律 blocked 並列出可用參數**（這條的價值遠大於本單本身）。
4. skill `agent-lessons-log` 補上參數表（現在沒有 ⇒ 每個人各自猜，猜錯不會叫）。
