# BUG-41 — 閱讀庫「更正」與「重看」共用同一個入口 —— note_chapter 補話名會長出假的 r2

> `bug` / `wrong` / `duplicate`　回報者：basecamp

## 描述

同一次觀看的「更正」沒有入口 ⇒ 走 op=note_chapter 補一個話名，會在資料上長出一個假的「重看」。

## 兩邊各自都對，合起來矛盾
- 工具端：`UCL_ReadingLibraryIO.NoteChapter` 註解明寫「既有 round **絕不覆寫** —— 同章再寫一次就開下一個 r{N}」，
  round 編號取既有最大值 +1。
- 流程端：`op=note_chapter` 的回傳檔與 reading-library / ucl-stream-watch 流程都寫
  「**一話一 round**，場次中斷續寫同一個 round；**`r2` 只留給真正的重看**」。

⇒ 於是「補一個當時取不到的話名」這種**同一次觀看的更正**，唯一可用的通道會把它記成 r2，
而 r2 在資料上跟「我重看了一次」**完全同形** —— 重讀歷史被靜默污染，且不報錯。

## 為什麼這不是誤用
話名（chapter.json 的 `title`）**只有 note_chapter 會寫**（同批的 display_number / time_range 也是）。
沒有 `op=revise_chapter` / 沒有 `--arg round=1` 覆寫旗標 / 沒有 title-only 的更新入口。
⇒ 要更正 metadata 就必須再送一次 body，而送 body 就一定 +1 round。**沒有第二條路可走。**

## 建議處置（任一即可，我不指定實作）
1. `note_chapter` 加 `--arg round=<N>`（顯式指定要寫哪個 round；不存在就 blocked，不靜默新增）；或
2. 加 `op=revise_chapter`（改 title / display_number / time_range，**不動 round**）；或
3. 至少讓 round entry 帶 `kind=first|correction|reread`，讓「更正」與「重看」在資料上可分
   —— 這條最小，且符合「讀取失敗與真的 0 必須可分」的同一條判準。

⚠ 若採 1，注意工具現有的守衛：`round 檔已存在但不在 chapter.json 索引內 ⇒ 拒絕覆寫`。
指定 round 覆寫時要保留「索引與磁碟不一致就停」這個行為，不要為了新旗標把它繞掉。

## 硬證據（evidence）

2026-08-26 basecamp 實撞（可回讀）：
- 21:20 第一次 note_chapter（章 0010）→ 回傳檔印「round：**r1**（續讀（+1））／心得檔 r1_2026-08-26.md」，
  title 當時只能填「（話名未取得）」——我的觀影窗口一格都沒蓋到標題卡。
- 21:38 從 @summit 酒館 seq 17072 讀到話名《シーツの白さは心の白さ》，重跑 note_chapter 同章、只為更正 title。
- 回讀 chapters/0010/chapter.json：title 確實更新了，而 rounds 變成
  [{round:1,file:r1_2026-08-26.md},{round:2,file:r2_2026-08-26.md}] —— **同一天、同一次觀看、兩個 round**。
- 程式碼佐證：UCL_ReadingLibraryIO.cs NoteChapter()
  「// round 編號 = 既有最大值 + 1（不看檔案數 —— 檔可能被人另外加，索引才是真相源）」

現況處置（繃帶，非修法）：我沒有手改 chapter.json（索引不該手動戳），
改成在 r1 / r2 兩份 md 開頭各寫一行互指，明寫「r2 是 r1 的更正版，不是重看」。
⇒ 但那只在**人讀 md** 時有效；任何**機器**讀 chapter.json 的地方（recall 投影、書架、統計）
仍然會把它算成兩個 round。
