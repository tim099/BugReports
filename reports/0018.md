# BUG-18 — Phase 1 收尾清單：仍直讀 legacy 的消費端（session_common / tavern_catchup / Treasury 兩支）

> `doc` / `wrong` / `duplicate`　回報者：kiara

## 描述

退場案 Phase 1 已落地（identity 欄搬進 `letters/<p>/profile/`，21 人全遷、legacy 只出不進），
但**還有三處消費端仍直讀 legacy**。它們今天都不出錯 —— 因為 legacy 還留著遷移那一刻的值，
兩邊剛好相同。**它們會在「有人改過 profile/」之後才開始給錯答案**，而那時沒有任何一格會紅。

本單是**待辦清單＋判準記錄**，不是回報壞掉的東西。每一項都附「為什麼今天不痛」。

## ① `awakening.py` 的 fork 來源（`cmd_fork` 系列）

`src = reg["personas"][source]` —— `load_registry` 已改走接縫（`f8807c5`），
所以這一項**其實已經好了**。留在清單裡是為了記下判準：
fork 抄 `identity_vector` / `fork_lineage` / `layer_role`，那三欄都在 profile/，
抄錯就是生一個帶過期血統的孩子。**驗收方式**：改某人 profile/ 的 layer_role 後 fork 他，
看孩子拿到新值還是舊值。

## ② `_lib/session_common.py` 的 `_PERSONAS_DIR`

讀的是 routing／bank 那一族（`agent` / `bank_account`），而**那幾欄留在 legacy 是對的**
（§8.3 綁專案組）⇒ 正確性上不痛。
但「persona 資料的入口」還是兩個（接縫 ＋ 自己的 `_PERSONAS_DIR`）——
Tim 2026-08-19 的方向是「能走 CMD 的就走 CMD」，這支該收。
⚠ 收之前要確認它的呼叫時機：若它會在 Cmd 執行中被跑到，需要 `UCL_PP_SKIP_CMD=1`
（同 `UCL_AwakeningService.RunBrief`／`UCL_LoginStatusPage` 那兩處的處理）。

## ③ `tavern_catchup.resolve_owning_agent`

同 ②：讀的是 agent 歸屬（routing），不碰 identity ⇒ 今天不痛，但入口該統一。

## ④ Treasury 兩支（`UCL_TreasuryAccountResolver` / `UCL_BankAdminPage`）

**明確擋著，不要先動** —— summit 2026-08-19 交接時拍板：
等 §8.1「bank 反向登記」（銀行端 `personas: []` 反向索引）一起做。
現在改成走接縫只會做一半，然後 §8.1 再改一次。
