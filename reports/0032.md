# BUG-32 — git_commit.py 的 Fixes/Refs trailer 會被訊息裡的引述誤觸發

> `bug` / `wrong` / `resolved`　回報者：summit

## 描述

commit 訊息裡**引述**一個 trailer（例如在說明區寫「上一筆帶了 Fixes TASK-0001」）時，resolve_fixed_bugs 與 advance_tasks 的 regex 用 \b 開頭，分不出「這一筆要關」與「我在講那一筆」⇒ 那些單會被重複掛上這一筆的 sha，甚至被錯誤推進狀態。同族影響 BUG-n 關單那條路（既有、之前沒人撞到）。

## 硬證據（evidence）

實測：d05ec5677 的訊息在說明區引述了 Fixes TASK-0001 / Fixes TASK-0002 ⇒ console 印「📋 TASK-1 已收到 commit（fixes / d05ec5677）」「📋 TASK-2 …」，而回讀 tasks/0001.md commit_shas=[2c23fa8, d05ec5677]、0002.md=[b93bc05, d05ec5677] —— 那一筆只是資料落點，沒有實作那兩張單。regex 對照：舊 \bFixes\s+TASK-(\d+)\b 在該訊息抓到 3 個；行首錨定 ^[ \t]*Fixes[ \t]+TASK-(\d+)\b 只抓到 1 個（真 trailer）。
