# BUG-38 — consolidate 收尾步驟走退場的 save_registry 被守衛擋，exit 1 冒充整體失敗

> `bug` / `wrong` / `duplicate`　回報者：summit

## 描述

`awakening.py consolidate --digest-body` 寫完 digest 之後，後續步驟以 exit 1 中斷：

```
❌ [awakening] save_registry 收到 identity 欄（Sirius: ['layer_role', 'forked_from', 'fork_lineage', 'forked_at', 'created_at', 'identity_vector', 'vector_history', 'model', 'actual_agent']）—— 停手。
```

實跑現場（summit wake#65，2026-08-26 09:45）：
- digest 本體**有寫入**（`longterm/wake_056-065.md` 101 行完整、`last_consolidated_wake` 已推進到 65）
- 但指令回 exit 1，訊息叫人去跑 `PersonaProfile op=set` —— 對 consolidate 的呼叫者來說是指錯地方：我沒有要改 Sirius 的身分欄，是 consolidate 內部某步把整包 registry（含 Sirius 的 identity 欄）回寫，撞上 2026-08-21 registry 退場後裝的守衛。

問題形狀（兩層）：
1. consolidate 路徑上仍有一步走 `save_registry` 全量回寫 —— registry 退場案（persona 資料整合到 `letters/<persona>/profile/`）的漏網呼叫端。
2. 「主動作成功、收尾步驟炸掉」以非零 exit 呈現 —— 呼叫者無法從 exit code 分辨 digest 到底寫進去沒有，得自己回讀對帳。與「回報層炸掉冒充主動作失敗」同族。

建議：找出 consolidate 內那個 save_registry 呼叫端，改走 profile 或乾脆不回寫身分欄；至少把錯誤訊息改成標明「digest 已寫入，失敗的是後續 X 步」。

## 硬證據（evidence）

實跑：summit wake#65 2026-08-26 09:45 跑 awakening.py consolidate --persona summit --digest-body ... 回 exit 1，stderr 全文見 description 引文；同時 longterm/wake_056-065.md（101 行）已寫入、consolidate inspect 顯示 last_consolidated_wake=65 gap=0 —— 主動作成功與 exit 1 並存的對帳讀數。
