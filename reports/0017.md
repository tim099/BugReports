# BUG-17 — persona_profile 接縫被同一行程載入三份 —— 不帶 SKIP_CMD 時是 3 次 Cmd 往返

> `suggestion` / `annoying` / `open`　回報者：kiara

## 描述

`_lib/persona_profile.py` 被**同一個 python 行程載入多份**，每份各有自己的 per-process 快取
⇒ 每多一份就多一次 Cmd 往返。

## 現象（實測）

`Cmd_GoodMorning step=brief` 的回傳檔 stderr 段，同一句話印了**三次**：

    ⚠ [persona_profile] 未走 Cmd：顯式跳過（UCL_PP_SKIP_CMD=1） —— 改讀快照（…）
    ⚠ [persona_profile] 未走 Cmd：顯式跳過（UCL_PP_SKIP_CMD=1） —— 改讀快照（…）
    ⚠ [persona_profile] 未走 Cmd：顯式跳過（UCL_PP_SKIP_CMD=1） —— 改讀快照（…）

`_load()` 有 module 級快取（`_STATE`），一份 module 只會印一次 ⇒ **印三次＝載了三份 module**。

## 為什麼會有三份

各消費端都用「顯式檔案路徑載入」繞開 `_lib` 名稱遮蔽（awakening.py 檔頭有註解說明
為什麼不能裸 `import _lib`），而 `spec_from_file_location` **每次呼叫都造一個新 module 實例**：

- `awakening.py` → `_ucl_persona_profile_for_awakening`
- `agent_email.py` → `_ucl_persona_profile_agent_email`
- `wake_brief.py`（被 awakening 匯入）→ 自己那一份

⇒ 名字不同、`sys.modules` 不共用 ⇒ 三個獨立的 `_STATE`。

## 危害

- **帶 `UCL_PP_SKIP_CMD=1` 時無害**（只是多讀兩次快照檔）
- **不帶的時候是 3 次 Cmd 往返**（每次 subprocess ＋ Editor queue 一輪，timeout 45s/次）。
  今天所有 C# spawn 的 python 都帶了 SKIP_CMD，所以現在不痛；
  但**任何從 CLI 直跑的路徑**（agent 自己跑 awakening.py / git_commit.py）都會付這個成本，
  而且它不會叫 —— 只是慢，而慢很容易被歸因到「Editor 忙」。

## 建議

把「載入接縫」收成一個共用 helper（例如 `_lib/_seam.py` 或在 ucl_paths 旁邊放一支
`load_seam()`），內部用**固定的 module 名字**做 `sys.modules` 快取 ⇒
第二個呼叫端拿到同一份實例。
⚠ 別用「大家都改成 `import _lib.persona_profile`」當修法 ——
那正是各檔用檔案路徑載入要繞開的那個名稱遮蔽問題（awakening.py 檔頭有血證）。

## 硬證：回傳檔逐字

`AgentCommands/ChatTavern/baton/letters/Template/cmd/goodmorning_brief.md`（2026-08-19 16:40:33）

    $ python awakening.py brief --persona Template   (exit=0)
    ── stderr ──
    ⚠ [persona_profile] 未走 Cmd：顯式跳過（UCL_PP_SKIP_CMD=1） —— 改讀快照（generated_at=2026-08-19T08:40:12.740Z），回傳值帶 _source 標記
    ⚠ [persona_profile] 未走 Cmd：顯式跳過（UCL_PP_SKIP_CMD=1） —— 改讀快照（generated_at=2026-08-19T08:40:12.740Z），回傳值帶 _source 標記
    ⚠ [persona_profile] 未走 Cmd：顯式跳過（UCL_PP_SKIP_CMD=1） —— 改讀快照（generated_at=2026-08-19T08:40:12.740Z），回傳值帶 _source 標記

三行的 `generated_at` 完全相同 ⇒ 同一次執行、同一份快照，只是被讀了三次。

## 快取是 module 級的（code）

`_lib/persona_profile.py`：

    # module 級狀態：每 process 解析一次。mode = "live" | "snapshot" | "local-parse"
    _STATE: dict = {"mode": None, "data": None, "snapshot_at": ""}

    def _load() -> dict:
        if _STATE["mode"] is not None:
            return _STATE["data"]      ← 一份 module 只會走一次那段 print

⇒ 印三次只有一個解釋：三份 module。

## 三個載入點（各自取了不同的 module 名字）

    awakening.py     spec_from_file_location("_ucl_persona_profile_for_awakening", …)
    agent_email.py   spec_from_file_location("_ucl_persona_profile_agent_email",  …)
    wake_brief.py    （被 awakening.py 匯入，自己再載一份）

`grep -rn "spec_from_file_location" | grep persona_profile` 可核。
